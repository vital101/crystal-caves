# Crystal Caves Ep.1 — Phase 5 shell notes

All addresses are load-module offsets (`file = load + 0x1E00`).

## Status

Phase 5 implements the title/credits/title flow, main menu, PCX screens, text
windows, the in-game HUD, help/pause/quit/warp/key-redefine screens,
story/finale transitions, save/restore, high scores, and browser config
persistence.  Gameplay remains deterministic and pixel-exact.

Known limitations:

- Text-window borders/fill are a faithful clean-room reproduction of the
  original blue window style, not yet oracle-diffed at the pixel level.
  The text glyphs, blocks, font mapping and centering are original.
- In-game message triggers cover the last-crystal, gravity and power-shot
  cases; the remaining exported message blocks are available through
  `cc_shell_message()` but not all cell/handler causes are wired yet.
- Key redefine stores browser `keyCode` values and persists them; it does not
  emulate DOS scan-code tables.
- Joystick uses the Gamepad API when present; the original calibration screen
  is informational.
- BBS/foreign/ordering/video options show the original text screens with
  browser-appropriate behaviour (no DOS file I/O or network calls).
- Sound is still Phase 6; the help sound toggle is stored/persisted.

## Assets

Generated by `tools/export_shell_assets.py`:

| Output | Meaning |
|---|---|
| `out/portable/screens.bin` | 4 × 320×200 indexed screens: APG, TTL, CDT, END |
| `out/portable/screens.json` | screen order/offsets |
| `out/portable/mni_f1.bin` | F1 glyphs, 50 × 40 B (3-byte MNI header stripped) |
| `out/portable/mni_f2.bin` | F2 glyphs |
| `out/portable/mni_spl.bin` | SPL glyphs (digits/icons) |
| `out/portable/shell_text.json` | extracted length-prefixed text blocks |
| `wasm/shell_text_data.h` | generated C block tables and enums |

PCX decode: v5, RLE, 4 planes, 40 bytes/line.  Runs are carried across
plane/scanline boundaries, which the original files require.  Display uses the
standard EGA palette (same as the level renderer).

Font format: 50 glyphs of 40 bytes; 3-byte MNI header stripped; each glyph is
8 rows × 5 bytes `[mask][plane0..plane3]`, MSB = leftmost pixel.  Glyph index
0 is the first byte after the header.

Text encoding: block text is ASCII, but the font's lowercase glyphs start six
codes later than ASCII lowercase.  `wasm/text.c` applies the original
`ch - 6` translation for `a`..`z`, then uses F1 for codes `0x17..0x48` and F2
for `0x49..0x7a`.  This yields the original upper/lowercase-looking glyphs.

## HUD (oracle-exact)

The real routine is `0x0FC5:0xD1E0` (linear `0x1CE30`).  It draws an 8-pixel
status row at `y = 1` with the glyph blitter `0x28B5:0x1A4D`.

- score: F1 icon 14 at cell 0; seven right-aligned SPL digits (glyph `d+8`)
  at cells 1..7.
- ammo: SPL icon 0 at cell 11; three right-aligned digits at cells 12..14.
- hearts: SPL glyph 4 at cell 19 + i.
- status icon: SPL glyph 5 at cell `20 + health`.
- power timer: F1 glyph 20 (`*`), two SPL digits, F1 glyph 20 at cells
  25/26..27/28; `[0xA0C4]` decrements when `[0xA0C6]` wraps at `0x11`.
- all-caves summary: `Crystals: ` label at cell 9 + 7 px and four SPL digits
  at cells 19..22.
- all x positions add `[0x512E] & 7`.

`tools/oracle_shell.py` runs the real routine with the original MNI buffers and
EGA plane hooks, producing `notes/hud_fixtures.json` (four boundary cases).
`wasm/test_hud.js` compares the C renderer against those fixtures.

## Shell state machine

`wasm/shell.c` implements:

```
LOGO -> CREDITS -> TITLE -> MENU -> TEXT/STORY -> GAME
GAME -> HELP/PAUSE/QUIT/SAVE/RESTORE/WARP -> GAME
GAME all-caves -> FINALE story -> ENDING -> HISCORE/NAME_ENTRY
```

Main-menu keys (scan-code letters in the original): N new game, R restore,
S story, I instructions, O ordering, H high scores, F foreign, C BBS, V video,
A about, Q/Esc quit.  Enter/Space start a new game.

In-game: Esc/F1 help, P pause.  Help: I instructions, T sound, J joystick,
C calibration text, V video, K key redefine, R restore, S save, Q quit,
W warp (hidden), Esc return.

Save/restore is hub-only, matching the original restriction.  The C layer
raises a request (`cc_shell_request_pending/kind/slot`); `game.html` stores or
loads `cc_state_save/cc_state_load` bytes from `localStorage` and calls
`cc_shell_request_done()`.  The snapshot is versioned (`CCS1`, v1) and includes
objects, cells, globals, RNG, cave flags, score/lives/ammo and checkpoints.

High scores and config use `localStorage` keys `cc1.hiscores.v1` and
`cc1.config.v1`.  High-score defaults are the original shareware names; the
table is sorted descending.  Config stores sound/joystick/video and four
browser key codes.
