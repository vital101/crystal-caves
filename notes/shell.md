# Crystal Caves Ep.1 — Phase 5 shell notes

All addresses are load-module offsets (`file = load + 0x1E00`).

## Status

Phase 5 implements the title/credits/title flow, main menu, PCX screens, text
windows, the in-game HUD, help/pause/quit/warp/key-redefine screens,
story/finale transitions, save/restore, high scores, and browser config
persistence.  Gameplay remains deterministic and pixel-exact.

Known limitations / deliberate browser substitutions:

- Keyboard bindings use IBM PC set-1 scan codes, matching the original port
  `0x60` input routine.  `wasm/keymap.js` maps browser `KeyboardEvent.code`
  values to those scan codes; E0-extended keys are normalized.
- The original blinking input cursor is not drawn in shell text windows; the
  `^` marker is treated as the input position and skipped by the printer.
- The title/credits scroll animation is approximated by the original
  432-tick combined duration; the exact per-frame scroll position is not
  reproduced.
- Joystick uses the Gamepad API when present; the original calibration screen
  is informational.
- BBS/foreign/ordering/video options show the original text screens with
  browser-appropriate behaviour (no DOS file I/O or network calls).
- Quit to DOS returns to the title screen.
- Sound is implemented in Phase 6 (`notes/sound.md`); the help sound toggle
  persists and follows the exact original `[0x513E]` gating semantics.
- `CC1.CFG`/`CC1.HS` file I/O is replaced by `localStorage` JSON.  The C-side
  high-score table and sort/name-entry rules are the original rules; only the
  storage format is a browser substitution.

## Assets

Generated by `tools/export_shell_assets.py`:

| Output | Meaning |
|---|---|
| `out/portable/screens.bin` | 4 × 320×200 indexed screens: APG, TTL, CDT, END |
| `out/portable/screens.json` | screen order/offsets |
| `out/portable/mni_f1.bin` | F1 glyphs, 50 × 40 B (3-byte MNI header stripped) |
| `out/portable/mni_f2.bin` | F2 glyphs |
| `out/portable/mni_spl.bin` | SPL glyphs (digits/icons) |
| `out/portable/shell_text.json` | extracted length-prefixed text blocks |
| `wasm/shell_text_data.h` | generated C block tables and enums |

PCX decode: v5, RLE, 4 planes, 40 bytes/line.  Runs are carried across
plane/scanline boundaries, which the original files require.  Display uses the
standard EGA palette (same as the level renderer).

Font format: 50 glyphs of 40 bytes; 3-byte MNI header stripped; each glyph is
8 rows × 5 bytes `[mask][plane0..plane3]`, MSB = leftmost pixel.  Glyph index
0 is the first byte after the header.

Text encoding: the original printer (`0x0FC5:0x06C4`, linear `0x10314`)
looks each character up in a 117-byte table at `CS:0x64C`: 32 leading `|`
entries, ASCII `0x20..0x5a`, then ASCII `0x61..0x7a`.  Characters `0x5b..0x60`
are absent and draw nothing.  The 1-based table position is the glyph code:
codes `<= 0x48` select F1 glyph `code-0x17`; codes `>= 0x49` select F2 glyph
`code-0x49`.  This reproduces the apparent six-code lowercase shift.  `^` is
the input cursor marker and is not printed by the window renderer.

## HUD (oracle-exact)

The real routine is `0x0FC5:0xD1E0` (linear `0x1CE30`).  It draws an 8-pixel
status row at `y = 1` with the glyph blitter `0x28B5:0x1A4D`.

- score: F1 icon 14 at cell 0; seven right-aligned SPL digits (glyph `d+8`)
  at cells 1..7.
- ammo: SPL icon 0 at cell 11; three right-aligned digits at cells 12..14.
- hearts: SPL glyph 4 at cell 19 + i.
- status icon: SPL glyph 5 at cell `20 + health`.
- power timer: F1 glyph 20 (`*`), two SPL digits, F1 glyph 20 at cells
  25/26..27/28; `[0xA0C4]` decrements when `[0xA0C6]` wraps at `0x11`.
- all-caves summary: `Crystals: ` label at cell 9 + 7 px and four SPL digits
  at cells 19..22.
- all x positions add `[0x512E] & 7`.

`tools/oracle_shell.py` runs the real routine with the original MNI buffers and
EGA plane hooks, producing `notes/hud_fixtures.json` (four boundary cases).
`wasm/test_hud.js` compares the C renderer against those fixtures.

Cadence: the original HUD's power-timer section runs once per game frame.
`cc_hud_tick()` performs only the `[0xA0C4]/[0xA0C6]` update (and returns early
when `[0xA0FB]` marks all caves complete); `cc_hud_render()` is now pure.
`game.html`/`play.html` call the tick once per `cc_objects_step_full()`.

## Text windows (oracle-exact)

The real window renderer is `0x0FC5:0x0877` (linear `0x104C7`), with the
string printer at `0x0FC5:0x06C4` and glyph blitter `0x28B5:0x0445`.
`wasm/text.c` reproduces it exactly:

- line buffer is `DS:0x163C`, stride `0x100`, starting at line 1; the
  `END OF WINDOW` sentinel ends the block.
- `maxlen = max(line_length - 1)`; `H = text_line_count + 2`;
  `wx = ((320 - maxlen*8)/2 + [0x512E])/8 - 3`;
  `wy = ((200 - H*8)/2 + [0x5130])/8 - 2`; all text/glyph y positions add
  `[0x2B5C]` (`cc_global_get(0x2B5C)` is now writable).
- interior is F1 glyph 8 tiled from `wx+1` to `wx+maxlen+3` for rows
  `wy+1..wy+H`; the frame uses F1 glyphs 0,1,2,5,7,9 (top), 4,6,3 (bottom)
  and glyph 9 for the (black) shadow.
- text starts at cell `wx+2`, line `i` at cell row `wy+i+1`; the `^` cursor
  marker is skipped by the printer.

`tools/oracle_shell.py` captures 14 real message wrappers (pause, last
crystal, stunned, more crystals, red mushroom, lever, power shot, poison, air
generator, gravity, perfect health, file error, saved, save-hub-only) plus
menu/story/instructions and camera/scroll variants into
`notes/text_fixtures.json`.  `wasm/test_text.js` reports 0 differing pixels
for all 23 cases (`make test-text`).  Shell UI windows are screen-space and
call `cc_text_draw_block()` with the game camera/scroll temporarily cleared,
then restore the player's camera globals.

## Shell state machine

`wasm/shell.c` implements:

```
LOGO -> CREDITS -> TITLE -> MENU -> TEXT/STORY -> GAME
GAME -> HELP/PAUSE/QUIT/SAVE/RESTORE/WARP -> GAME
GAME all-caves -> FINALE story -> ENDING -> HISCORE/NAME_ENTRY
```

Main-menu keys (scan-code letters in the original): N new game, R restore,
S story, I instructions, O ordering, H high scores, F foreign, C BBS, V video,
A about, Q/Esc quit.  Enter/Space start a new game.

In-game: Esc/F1 help, P pause.  Help: I instructions, T sound, J joystick,
C calibration text, V video, K key redefine, R restore, S save, Q quit,
W warp (hidden), Esc return.

The hidden warp is a debug load, not a door/exit transition: it uses the
destination's baked image (so source-cave leftover cells cannot leave Mylo in
a wall) while preserving score/lives/cave flags.

Save/restore is hub-only, matching the original restriction.  The C layer
raises a request (`cc_shell_request_pending/kind/slot`); `game.html` stores or
loads `cc_state_save/cc_state_load` bytes from `localStorage` and calls
`cc_shell_request_done()`.  The snapshot is versioned (`CCS1`, v1) and includes
objects, cells, globals, RNG, cave flags, score/lives/ammo and checkpoints.

High scores and config use `localStorage` keys `cc1.hiscores.v1` and
`cc1.config.v2`.  High-score defaults, qualification, sort/tie and name-entry
rules are the original rules (see below).  Config stores sound/joystick/video
and four DOS scan codes.  `cc1.config.v1` keys were browser `keyCode` values;
v1 is read only for sound/joystick/video and the keys reset to the DOS
defaults.

## Exactness verification (P5.R5)

`tools/shell_exactness.py` runs the original shell routines with a minimal
INT 21h file shim and scripted keyboard input.  It does not run the complete
menu flow; it captures the observable data needed by P5.R5.

Committed fixtures:

- `notes/shell_exactness_fixtures.json` — screen tick counts, intro/finale
  page line buffers, high-score screen lines and framebuffer hash.
- `notes/hiscore_fixtures.json` — default ten-row table, qualification cases,
  tie rule, name-entry limit.
- `notes/keymap_fixtures.json` — default scan codes and the original
  scan-code → label table.

`tools/make_shell_exact_data.py` turns the committed fixtures into
`wasm/shell_exact_data.h`.  Do not hand-edit that header; run
`make test-oracle-exactness` to regenerate, then `make data` in `wasm/`.

### Screen timing

The shell advances in PIT ticks at 140.06 Hz, not render frames.  The
original constants are:

| Stage | Timer | Approx. duration |
|---|---|---|
| Apogee logo | `[0x2B60] > 0x2D0` (720 ticks) | 5.14 s |
| Credits | 216 ticks | 1.54 s |
| Title | 216 ticks | 1.54 s |

The original title routine loads `cc1.cdt` and `cc1.ttl` and runs one
432-tick (3.08 s) scroll sequence.  The two 216-tick shell stages represent
the two captured screens; the scroll itself is approximated by the tick
cadence.

`cc_shell_step_ticks()` is the deterministic entry point; `game.html`
converts elapsed time to ticks at the same rate.  `cc_shell_step()` remains a
one-tick alias for tests.

### Story/finale order

The captured page order is:

- intro: ship's log page 1, log page 2a, log page 2b, encyclopedia page 1,
  encyclopedia page 2 (5 pages);
- finale: finale page, “Can he succeed…”, twibbles, twibbles2 (4 pages).

The line arrays include the original blank separator rows and the
`Press Any Key ^` marker, so they are rendered without the old fixed 18-line
block split.

### High scores

The original initializer (`0x0FC5:0x8738`) seeds the default ten-row table:

```text
150000 Play all 3 episodes
140000 of Crystal Caves.
130000 Call 1-800-852-5659
120000 and use Visa or MC.
110000
100000 I. Jones
 90000 B. Blaze
 80000 S. Logan
 70000 D. Nukem
 60000 J. Kirk
```

The qualification threshold is the last row (`score > 60000` on defaults).
The sort is descending and stable: equal scores keep the existing entry
first.  Name entry accepts up to 20 letters/digits/spaces; an empty name is
preserved (it is not replaced with `"Mylo"`).  The high-score screen is built
from the original line format (`" %-20s %u"`) and matches the captured
framebuffer.

### Key redefine

Defaults are DOS scan codes: left `0x4B`, right `0x4D`, jump `0x1D` (Ctrl),
fire `0x38` (Alt).  The redefine flow prompts for four keys, rejects
duplicates with the original “Sorry, that key is unavailable.” window,
shows the summary, and restarts on `N`; any other key accepts.  `Esc`
cancels.  `wasm/keymap.js` is the browser → set-1 scan-code adapter.
